PART A · UNIT I: WEB ESSENTIALS

Syllabus: The Internet and World Wide Web, Basic Protocols, Web Essentials (Clients, Servers and Communication), HTTP Request Message, HTTP Response Message, Web Clients, Web Servers, HTML5 Basic Elements.

1. The Internet

Definition The Internet is a worldwide network of networks. It connects billions of computers, phones and servers so they can share data.
  • History: It started in 1969 as ARPANET, a US defence project. In 1983 it adopted TCP/IP, which became the base of today's Internet.
  • No single person or company owns it. Groups like ICANN (names and addresses) and the IETF (standards) manage it.
  • Every device on it has an IP address, like a house address. Example: 142.250.183.14
  • Services that run on the Internet: the Web, email, file transfer, video calls, online games.

2. The World Wide Web (WWW)

Definition The WWW is a collection of linked documents (web pages) stored on servers around the world. You open them with a browser over the Internet. It was invented by Tim Berners-Lee at CERN in 1989.

The 3 building blocks of the Web

  1. HTML: the language used to write pages.
  2. URL (Uniform Resource Locator): the address of a page.
  3. HTTP: the rules for moving pages between server and browser.

Example: what happens when you type www.google.com and press Enter?
  1. The browser asks DNS: "What is the IP of www.google.com?" DNS replies with an IP address.
  2. The browser opens a TCP connection to that IP on port 443 (the "3-way handshake": SYN, SYN-ACK, ACK).
  3. A TLS handshake sets up encryption, because it's HTTPS.
  4. The browser sends an HTTP request: GET / HTTP/1.1
  5. Google's server sends an HTTP response: 200 OK plus the HTML.
  6. The browser reads the HTML, downloads CSS, JS and images, then renders (draws) the page.

4. Web Essentials: Clients, Servers and Communication

┌──────────────┐ HTTP Request ┌──────────────┐ │ CLIENT │ ────────────────────────▶ │ SERVER │ │ (Browser) │ │ (Web server) │ │ │ ◀──────────────────────── │ + files │ └──────────────┘ HTTP Response │ + database │ └──────────────┘
Real-life analogy: a restaurant You (the client) look at the menu and place an order (the request). The kitchen (the server) cooks the food and the waiter brings it to you (the response). The waiter is like HTTP.

Key points about communication

  • The client always starts the conversation. The server only answers.
  • HTTP is stateless: the server forgets you after each request. To remember you (for example, that you're logged in), websites use cookies, sessions or tokens.
  • Request–response cycle: one request, one response.
  • HTTP versions: HTTP/1.0 (one request per connection), HTTP/1.1 (keep-alive connections), HTTP/2 (many requests in parallel), HTTP/3 (runs over QUIC/UDP, faster).

7. Web Clients

Definition A web client is any software that sends HTTP requests and receives responses. The most common one is the web browser.
  • Examples: Chrome, Firefox, Edge and Safari (browsers); mobile apps; curl and Postman (testing tools); search-engine crawlers.
  • Jobs of a browser:
    1. Take the URL from the user
    2. Find the IP using DNS
    3. Send the HTTP request
    4. Receive the response
    5. Parse the HTML into the DOM and the CSS into the CSSOM, then render the page
    6. Run the JavaScript
    7. Store cookies, cache and history
  • Browser parts: user interface, rendering engine (Blink, Gecko, WebKit), JavaScript engine (V8, SpiderMonkey), networking, storage.

8. Web Servers

Definition A web server is software (and the computer it runs on) that waits for HTTP requests and sends back web pages or data.
  • Examples: Apache HTTP Server, Nginx, Microsoft IIS, Apache Tomcat (for Java), Node.js with Express.
  • How it works: listen on a port (80 or 443), accept the request, find the file or run code, build the response, send it.

1. Introduction to CSS

Definition CSS (Cascading Style Sheets) controls how a page looks: colours, fonts, spacing and layout.
HTML = the skeleton (structure). CSS = the clothes and makeup (style). JavaScript = the muscles (behaviour).

Why "cascading"? When several rules apply to the same element, the browser picks one based on priority, like water flowing down steps.

Advantages: saves time (one CSS file styles the whole site), smaller HTML, consistent look, easy to change, supports different screen sizes.

3. The Three Ways to Add CSS

(a) Inline CSS: inside the tag, using the style attribute

<h1 style="color: red; text-align: center;">Hello</h1>

✔ Quick for one element. ✘ Messy and can't be reused.

(b) Embedded / Internal CSS: inside a <style> tag in the head

<head>
  <style>
    h1 { color: green; }
    .note { background: yellow; }
  </style>
</head>

✔ Good for styling a single page. ✘ Can't be shared with other pages.

(c) External CSS: a separate .css file, linked in

<!-- index.html -->
<head>
  <link rel="stylesheet" href="style.css">
</head>

/* style.css */
body { font-family: Arial; background: #f0f0f0; }
h1   { color: navy; }

✔ Best way: one file styles the whole website, and the browser caches it. ✘ Needs an extra file download.

Exam point: priority (cascading order) Inline > Embedded/Internal ≈ External. Between internal and external, whichever comes later in the code wins.
Specificity: ID (100) > Class (10) > Element (1). Adding !important overrides everything.
Example: if p {color:red}, .x {color:blue} and #y {color:green} all match <p class="x" id="y">, the text is green.

Based on CO3: "Develop server side applications using Node.js". Check the exact topics against your full syllabus.

1. What is Node.js?

Definition Node.js is a runtime that lets JavaScript run outside the browser, on the server. It is built on Chrome's V8 engine. It was created by Ryan Dahl in 2009.

Features

  • Single-threaded with an event loop: one thread handles many users by not waiting around.
  • Non-blocking (asynchronous) I/O: while a file or database is loading, Node serves other requests.
  • Fast (V8 compiles JS to machine code).
  • npm (Node Package Manager) gives access to over 2 million free packages.
  • The same language (JS) on the front end and back end.
Analogy: blocking vs non-blocking Blocking: a waiter takes your order and stands in the kitchen until the food is ready. Nobody else gets served.
Non-blocking (Node): the waiter takes your order, gives it to the kitchen, serves other tables, and brings your food when the kitchen calls.

The event loop

Request ──▶ Event Queue ──▶ EVENT LOOP (single thread) │ slow work (file, DB, network) ▼ Thread pool / OS does the work │ when done → callback ▼ Callback queue ──▶ back to event loop ──▶ Response

Syllabus: Neural Networks and Representation Learning, Convolutional Layers, Implementing the Multichannel Convolution Operation, Train a CNN, Motivation, Pooling, Data Types.

1. Neural Networks and Representation Learning

Definition A neural network is a model made of layers of "neurons". Each neuron computes output = activation(w·x + b).
Representation learning means the network learns useful features on its own from raw data, instead of a human hand-designing them.
Example To recognise a cat, older methods needed humans to write rules like "detect whiskers". A deep network learns layer by layer: edges → shapes (eyes, ears) → whole objects (cat face).

2. Motivation: why CNNs instead of normal (dense) networks?

  • A 224×224 colour image has 224×224×3 = 150,528 inputs. A fully connected layer with 1000 neurons would need about 150 million weights. That is far too many.
  • CNNs use three ideas:
    1. Sparse (local) connectivity: each neuron looks at a small patch only (e.g. 3×3).
    2. Parameter sharing: the same filter slides over the whole image, so there are far fewer weights.
    3. Translation equivariance: a cat is detected wherever it appears in the image.

3. The Convolution Operation

A small matrix called a filter (or kernel) slides over the image. At each position you multiply element by element and add up the results. The output is called a feature map.

Worked example: 4×4 input, 2×2 filter, stride 1 
Input               Filter          Output (3×3)
1 2 0 1             1 0             1·1+2·0+0·0+1·1 = 2   ...
0 1 3 1      *      0 1      =      2  5  1
1 0 2 2                             0  3  5
2 1 0 1                             2  1  3
Top-left: (1×1)+(2×0)+(0×0)+(1×1) = 2. Then slide one step right and repeat.
Output size formula (very important) Output = ⌊(N − F + 2P) / S⌋ + 1
N = input size, F = filter size, P = padding, S = stride.
Example: N = 32, F = 5, P = 0, S = 1 gives (32 − 5)/1 + 1 = 28, so a 28×28 output.
With P = 2: (32 − 5 + 4)/1 + 1 = 32 (the size stays the same; this is called "same" padding).
  • Stride: how many pixels the filter moves each step. A bigger stride gives a smaller output.
  • Padding: adding zeros around the border so the edges aren't lost and the size is kept.

4. Multichannel Convolution

A colour image has 3 channels (R, G, B). So each filter also has 3 channels: its shape is F × F × Cin.

  • Convolve each channel with its matching filter slice, then add all the channels together and add the bias. The result is 1 feature map.
  • Using K filters gives K output channels.
  • Number of parameters = (F × F × Cin + 1) × K
Example Input 32×32×3, 10 filters of size 5×5, stride 1, no padding.
Output = 28×28×10. Parameters = (5×5×3 + 1) × 10 = 760.
# NumPy idea for one output pixel of one filter
out[i, j, k] = np.sum(x[i:i+F, j:j+F, :] * W[:, :, :, k]) + b[k]

5. Pooling

Definition Pooling shrinks the feature map (downsampling). It keeps the important information, reduces computation, and makes the network less sensitive to small shifts.
Input 4×4                 Max pool 2×2, stride 2     Avg pool 2×2, stride 2
1 3 | 2 4
5 6 | 1 0        ──▶          6   4                     3.75  1.75
----+----
2 2 | 7 8                     3   8                     2.0   6.25
1 3 | 5 5
  • Max pooling: takes the biggest value (most common).
  • Average pooling: takes the average.
  • Global average pooling: averages a whole feature map into one number.
  • Pooling has no learnable parameters.

6. Full CNN Architecture

Image ─▶ [Conv ─▶ ReLU ─▶ Pool] ─▶ [Conv ─▶ ReLU ─▶ Pool] ─▶ Flatten ─▶ Dense ─▶ Softmax ─▶ Class (feature extraction, repeated) (classification)

ReLU = max(0, x). It adds non-linearity. Softmax turns the outputs into probabilities that add up to 1.

7. Training a CNN

  1. Prepare the data: resize, normalise (divide pixel values by 255), split into train, validation and test sets.
  2. Forward pass to get predictions.
  3. Loss: cross-entropy for classification.
  4. Backpropagation computes gradients. An optimizer (SGD or Adam) updates the weights.
  5. Repeat for many epochs in mini-batches.
  6. Avoid overfitting with dropout, data augmentation (flip, rotate, crop), batch normalisation, early stopping and weight decay.

PART B · DEEP LEARNING UNIT IV: RECURRENT NEURAL NETWORKS

Syllabus: Key Limitation: Handling Branching, Automatic Differentiation, Motivation, Recurrent Neural Networks, Implementation of RNNs, RNN Nodes: Vanilla, GRU, LSTM.

1. Key Limitation: Handling Branching

A simple network built as a straight chain of layers (input → layer → layer → output) can't easily handle branching: when one value is used in two places, or two paths join together (as in RNNs and ResNets).

When a value feeds several paths, its gradient is the sum of the gradients flowing back from every path. Writing that by hand for every model is hard. Automatic differentiation solves this.

2. Automatic Differentiation (Autograd)

Definition Automatic differentiation computes derivatives (gradients) automatically. While the forward pass runs, it records every operation in a computational graph. It then applies the chain rule backwards through that graph.
Example f = (a + b) × b, with a = 2, b = 3.
Forward: c = a + b = 5, f = c × b = 15.
Backward: ∂f/∂a = b = 3. ∂f/∂b = c + b = 5 + 3 = 8. The gradient of b is the sum from its two paths: the branching case.
import torch
a = torch.tensor(2.0, requires_grad=True)
b = torch.tensor(3.0, requires_grad=True)
f = (a + b) * b
f.backward()
print(a.grad, b.grad)    # tensor(3.) tensor(8.)

3. Motivation for RNNs

  • Normal networks treat each input separately and have no memory.
  • Much data is sequential: order matters. Examples: sentences, speech, stock prices, weather, music.
  • Example: in "I grew up in France… I speak fluent ___", you need to remember "France" to predict "French".
  • An RNN keeps a hidden state (memory) that is passed from one time step to the next. It can also handle sequences of different lengths.

4. Recurrent Neural Network (Vanilla RNN)

Training: Backpropagation Through Time (BPTT)

Unfold the RNN over all time steps, then backpropagate. The gradient is multiplied by Whh again and again, which causes:

  • Vanishing gradients: values shrink toward 0, so the network forgets long-term information. Fix: LSTM or GRU.
  • Exploding gradients: values blow up. Fix: gradient clipping.

6. LSTM (Long Short-Term Memory)

Proposed by Hochreiter and Schmidhuber in 1997. It adds a cell state (Ct), a "conveyor belt" of long-term memory, controlled by 3 gates. Each gate is a sigmoid that outputs a value from 0 (block) to 1 (allow).

GateQuestion it answersFormula
Forget gate ftWhat old memory should be thrown away?σ(Wf[ht−1, xt] + bf)
Input gate itWhat new information should be stored?σ(Wi[ht−1, xt] + bi); candidate C̃t = tanh(…)
Output gate otWhat should be output now?σ(Wo[ht−1, xt] + bo)
Updates Ct = ft ⊙ Ct−1 + it ⊙ C̃t     ht = ot ⊙ tanh(Ct)
The cell state is updated by addition, so gradients flow easily and vanishing is greatly reduced.
Analogy Reading a story: the forget gate drops details of a minor character who left. The input gate notes the new hero's name. The output gate decides what's relevant to answer the current question.

7. GRU (Gated Recurrent Unit)

Proposed by Cho et al. in 2014. It's a simpler LSTM with 2 gates and no separate cell state.

  • Update gate zt: how much of the old memory to keep (like forget + input combined).
  • Reset gate rt: how much of the past to ignore when computing the new candidate.
  • ht = (1 − zt) ⊙ ht−1 + zt ⊙ h̃t

PART B · DEEP LEARNING UNIT V: AUTOENCODERS AND GENERATIVE MODELS

Syllabus: Regularized Autoencoders, Representational Power, Layer Size and Depth, Stochastic Encoders and Decoders, Denoising, Boltzmann Machines, Deep Belief Networks, Directed Generative Nets.

1. Autoencoder: the basic idea

Definition An autoencoder is a neural network trained to copy its input to its output. It does this through a narrow middle layer called the code (or bottleneck or latent space). This forces it to learn the most important features. It is unsupervised: no labels are needed.
Input x ─▶ [ ENCODER f ] ─▶ code h ─▶ [ DECODER g ] ─▶ Output r ≈ x (784) 784→128→32 (32) 32→128→784 (784) Loss = || x − g(f(x)) ||² (reconstruction error)
Analogy Summarising a 10-page chapter into 5 key points (the encoder), then rewriting the chapter from those 5 points (the decoder). If the rewrite is good, your 5 points captured the essence.

Uses: dimensionality reduction, denoising, anomaly detection (a high reconstruction error means unusual data, e.g. fraud), feature learning, image compression.

  • Undercomplete AE: the code is smaller than the input. It's forced to compress.
  • Overcomplete AE: the code is equal to or bigger than the input. It might just copy, so it needs regularisation.
  • A linear AE with MSE loss learns the same subspace as PCA.

2. Regularized Autoencoders

Instead of only making the code small, add a penalty to the loss so the AE learns useful properties. Loss = reconstruction + Ω(h).

TypeIdea
Sparse AEPenalty λ·Σ|hi|: only a few neurons are active at a time
Denoising AE (DAE)Input is corrupted, output should be the clean version (see below)
Contractive AE (CAE)Penalises the derivative of h with respect to x, so small input changes don't change the code much (robust features)

3. Representational Power, Layer Size and Depth

  • Even a single-hidden-layer encoder can in theory represent any mapping (the universal approximation theorem), but it may need a huge number of neurons.
  • Deep autoencoders (many layers in the encoder and decoder) can:
    • Represent the same function with far fewer parameters.
    • Need less training data.
    • Give better compression than shallow or linear ones.
  • A common way to train deep AEs: greedy layer-wise pretraining. Train a stack of shallow AEs one at a time, then fine-tune the whole network.
  • Layer size: too small a code underfits (loses information); too large and it just copies the input.

4. Stochastic Encoders and Decoders

Instead of a fixed output, the encoder and decoder output probability distributions:

  • Encoder: pencoder(h | x). Decoder: pdecoder(x | h).
  • Training minimises −log pdecoder(x | h). For real values (a Gaussian), this is the same as MSE. For binary values (Bernoulli), it's cross-entropy.
  • Leads to the Variational Autoencoder (VAE): the encoder outputs a mean μ and spread σ; we sample h = μ + σ·ε (the reparameterisation trick). Loss = reconstruction + KL divergence. We can then generate new data by sampling h and decoding it.

5. Denoising Autoencoders

clean x ─▶ add noise ─▶ x̃ (corrupted) ─▶ Encoder ─▶ h ─▶ Decoder ─▶ r Loss = || x − r ||² (compare with CLEAN x)
  • Noise types: Gaussian noise, masking (randomly set pixels to 0), salt-and-pepper.
  • The network can't simply copy, so it must learn the real structure of the data.
  • Example: cleaning noisy scanned documents or old photos.
noisy = x_train + 0.3 * np.random.normal(size=x_train.shape)
autoencoder.fit(noisy, x_train, epochs=10)    # input = noisy, target = clean

6. Boltzmann Machines

Definition A Boltzmann Machine (BM) is an energy-based, undirected, stochastic network of binary units. Low-energy states are more likely. P(x) = e−E(x) / Z, where Z is the normalising constant (the partition function).
  • It has visible units v (the data) and hidden units h (features).
  • In a full BM every unit connects to every other unit, which makes it very slow to train.

Restricted Boltzmann Machine (RBM)

Hidden: (h1) (h2) (h3) │ ╲ ╱ │ ╲ ╱ │ connections ONLY between layers │ ╳ │ ╳ │ NO visible–visible or hidden–hidden links Visible: (v1) (v2) (v3) (v4)
  • Energy: E(v, h) = −bᵀv − cᵀh − vᵀWh
  • Because there are no links within a layer, the hidden units are independent given v, which makes sampling easy.
  • Trained with Contrastive Divergence (CD-k) using Gibbs sampling: v → h → v' → h', then update W ∝ (v·hᵀ)data − (v'·h'ᵀ)model.
  • Uses: recommender systems (the Netflix prize), feature learning, pretraining.

7. Deep Belief Networks (DBN)

  • Proposed by Geoffrey Hinton in 2006. This kick-started modern deep learning.
  • Built by stacking RBMs. The hidden layer of one RBM becomes the visible layer of the next.
  • Structure: the top two layers are undirected (an RBM). The lower layers are directed (pointing down toward the data).
  • Training:
    1. Greedy layer-wise pretraining (unsupervised): train RBM 1, freeze it, train RBM 2 on its outputs, and so on.
    2. Fine-tuning (supervised): add an output layer and train everything with backpropagation.
Top RBM (undirected) h3 ═══ h2 ↓ directed h1 ↓ directed v (data)

8. Directed Generative Nets

Models that generate new data by sampling a random code z and passing it through a network: z → network → x.

ModelMain idea
Sigmoid Belief NetworksDirected graph of binary sigmoid units; each layer generates the one below
Differentiable Generator NetworksA neural net g(z) turns simple noise (Gaussian) into complex data
Variational Autoencoder (VAE)Encoder + decoder trained to maximise the ELBO (reconstruction − KL); smooth latent space
Generative Adversarial Network (GAN)Two networks compete: the Generator makes fakes, the Discriminator spots fakes. Both improve until the fakes look real.
Autoregressive nets (PixelCNN, WaveNet)Generate one piece at a time: p(x) = Π p(xi | x1..i−1)
GAN analogy The generator is a forger making fake currency notes. The discriminator is a police officer checking them. As the police get better, the forger improves, until the fakes can't be told apart. Used for realistic faces (StyleGAN), image-to-image translation and super-resolution.
GAN loss (minimax game) minG maxD   E[log D(x)] + E[log(1 − D(G(z)))]
